# Матрица трассировки требований (Traceability Matrix)

Документ связывает бизнес-потребности, требования, архитектурные решения и методы тестирования. 
Каждое требование из `requirements.md` должно иметь «обратный путь»: **Требование → Потребность → Тест**.

| ID Требования | Формулировка (кратко) | Чья потребность (Персона) | Архитектурное решение (ЛР 2В) | Как проверим (Тест) | Состояние |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **FR-01** | Поиск вещей с фильтром по датам | Арендатор (хочет найти свободную вещь) | Индексы в БД (PostgreSQL), кэширование запросов в Redis | `test_search_availability.py`: Поиск по дате исключает занятые вещи | В работе |
| **FR-02** | Авт. расчет стоимости и залога | Арендатор (боится скрытых комиссий) | Сервис калькуляции (Backend Python) | `test_price_calculation.py`: Формула (Цена * Дни) + Залог = Итог | В работе |
| **FR-03** | Безопасная оплата (Эскроу) | Арендатор и Владелец инструмента (боятся мошенничества) | Интеграция с API платежного шлюза (СБП/ЮKassa), таблица `transactions` | `test_payment_escrow.py`: Статус транзакции «Frozen» до возврата | Запланировано |
| **FR-04** | Блокировка дат в календаре | Владелец инструмента (хочет контролировать график) | Таблица `listing_availability`, UI-календарь на React | `test_availability_blocking.py`: Заблокированная дата недоступна для брони | В работе |
| **FR-05** | Интерфейс модератора для споров | Платформа (нужно объективно решить конфликт) | Роль `moderator` в RBAC, отдельный модуль админки | `test_dispute_resolution.py`: Изменение баланса после решения модератора | В работе |
| **NFR-01** | Скорость поиска ≤ 300 мс (p95) | Арендатор (ищет с телефона) | Индексы БД, CDN для статики, оптимизация SQL-запросов | Нагрузочный тест (JMeter): 20 RPS, замер p95 | Запланировано |
| **NFR-02** | Доступность (Uptime) ≥ 99.9% | Система (бизнес не должен терять деньги) | Kubernetes, Health-checks, балансировка нагрузки | Мониторинг Grafana/Prometheus | Запланировано |
| **NFR-03** | Шифрование данных (AES-256) | Все пользователи (защита приватности) | Настройка PostgreSQL (TDE), HTTPS (TLS 1.3) | Пентест, проверка SSL-сертификатов | Запланировано |
| **C-01** | Стек: Python, React, PostgreSQL | Команда (ограничение компетенций) | Выбор фреймворков Django и React | Ревью кода, `requirements.txt` | В работе |
| **C-02** | Только Web-версия (без мобильного) | Ограничение курса (время/ресурсы) | Адаптивный дизайн (Mobile-friendly CSS) | Не проверяется (ограничение) | В работе |

---

## Легенда статусов:
*   **Выполнено** — требование реализовано и проверено.
*   **Готово** — реализовано, но тесты еще прогоняются.
*   **В работе** — находится в разработке.
*   **Запланировано** — будет реализовано в следующих итерациях.
