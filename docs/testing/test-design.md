# Проектирование тестов TutBerry (ЛР 5)

Основание: [функциональные и нефункциональные требования](../requirements.md), [стратегия тестирования](strategy.md). Здесь разделены **уже автоматизированные проверки** и **запланированные случаи**. Ожидаемый результат — критерий для теста, а не заявление, что сценарий уже реализован.

## 1. Классы эквивалентности и границы периода аренды

В TutBerry даты начала и окончания **включаются** в период: `RentalPeriod.days = (end - start) + 1`. Поэтому интервалы, имеющие общую календарную дату, пересекаются; соседние периоды без общей даты — нет.

| ID | Входные данные | Класс / граница | Ожидаемый результат | Автоматизация |
| --- | --- | --- | --- | --- |
| TD-01 | 01.01.2030–01.01.2030 | Одна дата, минимальная длина | 1 день | Запланировано |
| TD-02 | 01.01.2030–03.01.2030 | Допустимый период | 3 дня | Частично: `test_booking_service.py` |
| TD-03 | 02.02.2030–01.02.2030 | Конец раньше начала | `BookingError` | Есть: `test_invalid_period_rejected` |
| TD-04 | 01.01–02.01 и 02.01–03.01 | Общая граничная дата | Пересечение | Есть: `test_inclusive_period_and_overlap` |
| TD-05 | 01.01–02.01 и 03.01–04.01 | Соседние без общей даты | Нет пересечения | Запланировано на уровне домена |
| TD-06 | Блокировка 10.06–12.06, бронь 12.06–13.06 | Совпадение граничной даты | HTTP 409 | Есть: `test_owner_calendar_block_rejects_overlapping_booking_but_allows_adjacent_dates` |
| TD-07 | Блокировка 10.06–12.06, бронь 13.06–14.06 | Первая свободная дата | HTTP 201 | Есть: тот же тест |

## 7. Проверка «на сломанный код»

Изменения вносить **по одному**, локально или в отдельной ветке, затем откатывать. В `main` намеренно неисправный код не сохранять.

| Мутация | Что изменить | Какой тест должен обнаружить |
| --- | --- | --- |
| M-01 | В `RentalPeriod.overlaps` заменить `<=` на `<` | `test_inclusive_period_and_overlap` |
| M-02 | Убрать `+ 1` из `RentalPeriod.days` | `test_inclusive_period_and_overlap`, `test_booking_created_with_fixed_price_and_notification` |
| M-03 | В `BookingPrice.total` не прибавлять залог | `test_booking_created_with_fixed_price_and_notification` |
| M-04 | Разрешить `approve` для `cancelled` | `test_booking_lifecycle_and_cancelled_guard` |
| M-05 | Убрать проверку владения объявлением при создании брони | `test_validation_and_owner_permission_problem_details` |

Это **план**, а не результат мутационного прогона. Итоги каждой проверки записываются в `metrics.md`.
