# Полноценный мутационный анализ доменной модели

В лабораторной № 5 предусмотрен мутационный балл по предметной области **не ниже 70%**. Ранее автоматизированная проверка пяти заранее выбранных ошибок (`scripts/mutation_smoke.py`) обнаружила 5/5, но **это не полноценный mutation score**.

## Реализация

Добавлен отдельный workflow [`.github/workflows/mutation-analysis.yml`](../../.github/workflows/mutation-analysis.yml) с ручным запуском через GitHub Actions → Mutation analysis (manual) → Run workflow (ветка `lab05-quality`).

- Инструмент: `mutmut>=2.4,<3` — версия 2.x, как в методичке.
- Модуль: `tutberry/domain/booking.py`.
- Набор проверки: `tests/test_booking_domain.py`.
- Перед мутациями выполняется базовый прогон тестов.
- Результаты сохраняются как артефакт `booking-domain-mutation-results`.
- Анализ не включён в обычный CI, поскольку он существенно дольше стандартных тестов.

## Интерпретация

После выполнения необходимо открыть `mutation-results.txt`, посчитать долю обнаруженных осмысленных мутаций, разобрать выжившие и исключить эквивалентные мутации с обоснованием. **Цель — не менее 70%**.

**Статус:** workflow создан, фактический запуск и мутационный балл пока не подтверждены. Успешные 5/5 контрольных мутаций нельзя выдавать за выполнение порога 70% для всего доменного модуля.
