# Полноценный мутационный анализ доменной модели

В лабораторной № 5 предусмотрен мутационный балл по предметной области **не ниже 70%**. Ранее автоматизированная проверка пяти заранее выбранных ошибок (`scripts/mutation_smoke.py`) обнаружила 5/5, но **это не полноценный mutation score**.

## Реализация

Добавлен отдельный workflow [`.github/workflows/mutation-analysis.yml`](../../.github/workflows/mutation-analysis.yml) с автоматическим запуском при изменениях workflow или доменных тестов в ветке `lab05-quality` (а также поддержкой ручного запуска).

- Инструмент: `mutmut>=2.4,<3` — версия 2.x, как в методичке.
- Модуль: `tutberry/domain/booking.py`.
- Набор проверки: `tests/test_booking_domain.py` и `tests/test_booking_mutation_boundaries.py`.
- Перед мутациями выполняется базовый прогон тестов.
- Результаты сохраняются как артефакт `booking-domain-mutation-results`.
- Анализ не включён в обычный CI, поскольку он существенно дольше стандартных тестов.

## Интерпретация

После выполнения необходимо открыть `mutation-results.txt`, посчитать долю обнаруженных осмысленных мутаций, разобрать выжившие и исключить эквивалентные мутации с обоснованием. **Цель — не менее 70%**.

**Статус:** запуск состоялся и результат подтверждён: 82,7% (43/52). Успешные 5/5 контрольных мутаций нельзя выдавать за выполнение порога 70% для всего доменного модуля.

## Измерение 21.11.2026

По предоставленному логу запуска `mutmut` обнаружены **43 из 52** созданных мутаций, **9 выжили**, прерванных/подозрительных/пропущенных нет. Мутационный балл — **82,7%** (`43 / 52 × 100`), что **выше порога 70%**. Ранее прогон имел 25/52 (48,1%).

Код выхода `2` у `mutmut` сам по себе не означает, что порог не пройден: есть выжившие мутации. С коммита `90e48a6` workflow отдельно проверяет численный балл и не считает наличие отдельных выживших мутаций автоматическим провалом. После добавления численного порога пользователь подтвердил успешный статус `domain-mutation`.
