# Лабораторная работа № 5 — инженерия качества TutBerry

## Цель

Проверить качество реализованной части сервиса аренды инструментов с помощью автоматических тестов, статического анализа, проверки API-контракта, контролируемых мутаций и подготовки нагрузочных сценариев.

Работа ведётся в отдельной ветке `lab05-quality`. Локальный Docker для изменений не требуется: файлы сохраняются в GitHub, а проверки запускаются в GitHub Actions.

## Зафиксированные результаты

- Базовый локальный прогон: **25 тестов прошли**, покрытие **93%** (441 оператор, 33 пропущены).
- Ruff и mypy: успешные проверки в ранее подтверждённом CI.
- Пять выбранных контрольных мутаций: **5/5 обнаружены**; это результат именно выбранного набора, а не полный mutation score проекта.
- Порог покрытия: **80%**, основной прогон pytest: не более **60 секунд**.
- Пять повторных прогонов pytest прошли в CI #12 без зафиксированных падений; также успешно завершились CI #13 и CI #14 (по скриншоту GitHub Actions от 21.11.2026).

## Ограничения и незавершённые проверки

1. k6-сценарии обращаются к существующему `GET /health`. Smoke-тест успешно прошёл в GitHub Actions (коммит `87a060f`), saturation #1 — также успешно (коммит `986fcd4`). Они **не измеряют производительность поиска**.
2. Для проверки NFR-01 необходимо реализовать маршрут поиска, подготовить 50 000 активных объявлений и измерить p95 при 20 запросах/с. Подтверждения соответствия NFR-01 пока нет.
3. Для `/health` пороги k6 smoke пройдены (GitHub Actions Load smoke #1, коммит `87a060f`); saturation #1 (коммит `986fcd4`) завершился успешно за около 5 минут. Точные значения p50/p95/p99, доля ошибок и отброшенные итерации на скриншотах не видны. Для поиска измерений нет.
4. Пять повторных прогонов CI прошли успешно, но это не доказывает отсутствие нестабильности в иных условиях.
5. Часть тест-кейсов из [test-design.md](test-design.md) относится к будущим функциям и пока не реализована.

## Вывод

Для реализованной части TutBerry подготовлен набор проверок качества: тесты, статический анализ, проверка API-контракта, пороги покрытия и времени, а также контрольные мутации. GitHub Actions позволяет выполнять эти проверки без локального запуска приложения. Повторные прогоны в CI подтверждены; для окончательной оценки производительности остаются нагрузочные испытания после реализации поиска. Результаты, которые ещё не измерены, не считаются успешно пройденными.
