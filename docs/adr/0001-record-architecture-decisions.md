# ADR-0001: Вести журнал архитектурных решений в репозитории

**Статус:** принято как проектное решение  
**Основание:** требования и модель предметной области TutBerry

## Контекст

Для TutBerry выбираются технологии, способ разделения модулей и правила безопасности. Эти решения затрагивают несколько частей системы, а их изменение может потребовать переработки кода и документации.

## Движущие факторы

- Необходимо сохранять причины выбора между архитектурными альтернативами.
- Решения используются при проектировании, изменениях и защите проекта.
- Документация должна версионироваться вместе с исходным кодом.

## Рассмотренные варианты

| Вариант | Преимущества | Недостатки |
|---|---|---|
| **Отдельные Markdown-файлы по формату MADR** | Версионирование в Git, удобные ссылки, одно решение в одном файле | Требует поддержки актуальности |
| Единый раздел в архитектурном обзоре | Все решения находятся в одном документе | Историю отдельных решений трудно отслеживать |
| Записи в системе задач | Удобная привязка к задачам | Решения отделяются от кода и могут теряться при переносе проекта |

## Решение

Применяется каталог `docs/adr/`. Каждое значимое решение получает отдельный файл с последовательным четырёхзначным номером. Обязательные разделы: контекст, движущие факторы, альтернативы, выбор, последствия и условие пересмотра. При изменении решения старая запись сохраняется с отметкой о замене, а новая получает следующий номер.

## Последствия

**Положительные:** Причины решений доступны вместе с проектом; изменения можно проследить по Git.

**Отрицательные:** На подготовку и поддержку записей требуется дополнительное время.

**Условие пересмотра:** Появление обязательного для проекта формата архитектурной документации, несовместимого с MADR.
