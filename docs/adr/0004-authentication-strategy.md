# ADR-0004: Использовать JWT с обновлением токенов и серверной проверкой прав

**Статус:** принято как проектное решение  
**Основание:** требования и модель предметной области TutBerry

## Контекст

Пользователи TutBerry могут быть арендаторами, владельцами и модераторами. API должен различать роли, защищать чужие объявления и брони, поддерживать выход из системы и обновление доступа.

## Движущие факторы

- `NFR-03`: защита персональных данных и TLS 1.3.
- `FR-04`–`FR-07`: операции доступны только участникам с соответствующими правами.
- `docs/api/resources.md`: JWT в заголовке `Authorization: Bearer` и эндпоинты `/auth/login`, `/auth/refresh`, `/auth/logout`.
- `C-01`: Django.

## Рассмотренные варианты

| Вариант | Преимущества | Недостатки |
|---|---|---|
| **Короткоживущий JWT + refresh-токен** | Совместим с существующим API, подходит для React и Django, масштабируемая проверка подписи | Необходима безопасная ротация и отзыв refresh-токенов |
| Серверные сессии Django | Отзыв сессий прост, зрелый механизм | Потребуется изменить уже описанный контракт Bearer JWT |
| Внешний OpenID Connect | Готовые сценарии единого входа | Дополнительный внешний сервис и усложнение учебного проекта |

## Решение

Используются подписанные JWT: access-токен сроком **15 минут**, refresh-токен сроком **7 дней** с ротацией и серверным отзывом при выходе. В токен помещаются минимальные сведения (`user_id`, роль, срок действия), без паспортных данных и телефонов. Проверка подписи и срока действия обязательна для закрытых эндпоинтов. Для операций с объявлением и бронью отдельно проверяется принадлежность ресурса; роль из клиентского интерфейса не считается достаточным основанием. Пароли хранятся в виде стойких хешей (Argon2id). Для браузерного клиента refresh-токен предусматривается в защищённом `HttpOnly`, `Secure`, `SameSite` cookie с защитой от CSRF для операций обновления/выхода. **Определяющий довод:** совместимость с уже описанным JWT API.

## Последствия

**Положительные:** Единый способ доступа к API, минимальный состав данных в токене, ограниченное время жизни доступа.

**Отрицательные:** Нужно хранить сведения для отзыва refresh-токенов и защищать cookie от CSRF; access-токен может оставаться действительным до истечения 15 минут.

**Условие пересмотра:** Требование немедленно отзывать любой access-токен либо переход на единую систему входа.
