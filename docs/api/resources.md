# Спецификация REST API — АИС «TutBerry»

Все запросы к API выполняются по базовому URL: `https://api.tutberry.ru/api/v1`
Формат обмена данными: `application/json`. Авторизация происходит через JWT-токены (заголовок `Authorization: Bearer <access_token>`).

## 1. Аутентификация и профиль (`/auth`, `/users`)
*Управление доступом, регистрация и настройки аккаунта.*

| Метод | Эндпоинт | Описание | Роли | Коды ответов |
| :--- | :--- | :--- | :--- | :--- |
| `POST` | `/auth/register` | Регистрация пользователя (email, пароль, имя) | Все | 201, 400, 409 |
| `POST` | `/auth/login` | Авторизация, получение JWT (access + refresh) | Все | 200, 401 |
| `POST` | `/auth/refresh` | Обновление access-токена | Все | 200, 401 |
| `POST` | `/auth/logout` | Выход из системы (отзыв токена) | Авторизованные | 204 |
| `GET` | `/users/me` | Получение данных текущего профиля | Авторизованные | 200, 401 |
| `PATCH` | `/users/me` | Обновление профиля (имя, аватар, контакты) | Авторизованные | 200, 400 |
| `GET` | `/users/{id}/reviews` | Получение публичных отзывов о пользователе | Все | 200, 404 |

## 2. Каталог и объявления (`/listings`)
*Управление карточками инструментов и их доступностью.*

| Метод | Эндпоинт | Описание | Роли | Коды ответов |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/listings` | Поиск объявлений (`?category=&min_price=&dates=`) | Все | 200 |
| `GET` | `/listings/{id}` | Получение детальной информации об объявлении | Все | 200, 404 |
| `POST` | `/listings` | Создание черновика объявления | Владелец | 201, 400, 401 |
| `PATCH` | `/listings/{id}` | Редактирование объявления | Владелец (свой) | 200, 403, 404 |
| `DELETE` | `/listings/{id}` | Снятие объявления с публикации | Владелец (свой) | 204, 403 |
| `POST` | `/listings/{id}/submit` | Отправка объявления на модерацию | Владелец | 200, 400 |
| `GET` | `/listings/{id}/availability` | Получение календаря занятых/свободных дат | Все | 200, 404 |
| `POST` | `/listings/{id}/availability` | Добавление или блокировка дат в календаре | Владелец | 201, 400 |
| `DELETE` | `/listings/{id}/availability/{date_id}` | Удаление блокировки даты | Владелец | 204, 403 |

## 💡 Примечания по реализации
1. **Идемпотентность:** Эндпоинты создания платежей (`POST /payments/...`) должны поддерживать заголовок `Idempotency-Key` для предотвращения двойного списания средств.
2. **Пагинация:** Все эндпоинты, возвращающие списки (`GET /listings`, `GET /bookings`), поддерживают параметры `?limit=20&offset=0`.
3. **Коды ошибок:** 
    *   `400` — Некорректный запрос (ошибка валидации).
    *   `401` — Не авторизован (отсутствует или истек токен).
    *   `403` — Доступ запрещен (недостаточно прав).
    *   `404` — Ресурс не найден.
    *   `409` — Конфликт (например, выбранные даты уже заняты).
