# ЛР 4А — результаты EXPLAIN ANALYZE

## Условия

PostgreSQL 17, тестовая база CI, 30 000 записей бронирований одного арендатора. Запрос: выбор последних 20 бронирований по `tenant_id` с сортировкой `start_date DESC`. Сравнение выполнено скриптом `scripts/explain_booking_indexes.sql`, результаты предоставлены в артефакте `lab04-explain-booking`.

| Показатель | Без индекса | С индексом |
|---|---|---|
| План | Seq Scan + Sort (top-N heapsort) | Index Scan |
| Execution Time | 6.917 ms | 0.031 ms |
| Planning Time | 0.160 ms | 0.149 ms |
| Буферы | shared hit=429 | shared hit=1, read=2 |
| Строк в выборке | 20 | 20 |

Отношение времён выполнения: `6.917 / 0.031 ≈ 223.1`. В рамках **одного тестового запуска** запрос с индексом оказался приблизительно в 223 раза быстрее. Это не гарантия аналогичного ускорения на других объёмах данных, распределениях арендаторов и аппаратном обеспечении.

## Объяснение

Без индекса PostgreSQL читает 30 000 строк и сортирует найденные записи. После создания `booking_tenant_recent_idx (tenant_id, start_date DESC)` планировщик выбирает Index Scan и может вернуть первые 20 строк в требуемом порядке, не сканируя всю таблицу.

## Воспроизводимость и ограничения

Бенчмарк предназначен только для изолированной тестовой базы: временно удаляет и пересоздаёт индекс, вставляет тестовые записи, затем удаляет их. Для большей достоверности нужны несколько прогонов и тестирование на реалистичных распределениях данных. Времена относятся только к указанному запросу; индекс `booking_active_start_idx` этим тестом отдельно не оценивался.
