# Первичный аудит тестируемости (ЛР 3Б)

## Границы

- HTTP-слой: Django REST Framework; проверяется через Django test client без сетевого сервера.
- Настройки: внешние переменные окружения, обязательные ключ и PostgreSQL DSN.
- Журнал: middleware, идентификатор запроса возвращается в HTTP-заголовке.
- Предметная область: агрегаты Listing, Booking и Payment определены в docs/domain/aggregates.md; код ещё не реализован.

## Швы

1. Настройки Django в тестах можно заменять через override_settings.
2. HTTP-запросы заменяются вызовами тестового клиента.
3. Будущий BookingService должен получать интерфейсы репозитория, часов и отправки событий через конструктор, а не создавать зависимости внутри.
4. Платёжный шлюз — внешний порт PaymentGateway; тесты используют дубль, не реальные деньги.

## Риски

- Текущие HTTP-тесты не проверяют настоящую базу данных.
- Отсутствуют доменные тесты и реализации агрегатов.
- Пока не добавлены проверки границ слоёв и единого языка.
- Для полного соответствия методичке необходимо согласовать Django вместо FastAPI.
